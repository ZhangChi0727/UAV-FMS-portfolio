## 修复一 成功条件与覆盖不能被删弱 P1

实测仍通过：reset_replay_match 的 limit=false；删除饱和持续时间上界；
删除 stale_timestamp 事件但仍保留拒绝次数为 2 的准则。

1. 对必须成功的布尔指标固定成功含义，至少 reset_replay_match 和
   limitation_event_recorded 应要求 true；不能仅限制 operator 为 ==。
2. 将“饱和触发下界”和“全程饱和上界”作为不同的必需验收角色校验，
   即使二者使用相同 metric，也不可相互替代。检查各自事件/全程窗口和上下界可行性。
3. invalid_input_and_reset 必须同时覆盖负 dt、陈旧 timestamp 和 reset。
   定义每次注入的目标、一次拒绝计数的口径、可见证据及允许次数；拒绝次数必须与事件覆盖一致。
4. 缺少一种事件、重复另一种事件凑数、把计数阈值改成 0，都不得让覆盖检查通过。

验收反例：false 成功值、删除/反转饱和上界、删除陈旧事件、重复负 dt 替代陈旧事件、
计数与事件不一致均被定位拒绝；合法上下界和完整覆盖可通过。

## 修复三 逐轴积分验收与饱和时间定义 P1

当前积分限值为 [0.15,0.15,0.10] Nm，但场景将全轴最大绝对值统一与 0.15 比较，
会放过 z=0.12 Nm。文档声称逐轴而配置不是。

- 选择逐轴准则，或采用 max_i(abs(I_i)/I_limit_i) <= 1 的无量纲准则。
  配置必须引用相应控制限值，校验器检查单位、轴覆盖和阈值一致，禁止漏轴/错轴。
- 同步 metric 定义、硬编码语义表、场景和文档，不能只锁住错误的旧聚合字符串。
- 饱和时间统一选择“任意轴饱和的时间并集”，每 tick 只累计一次 dt；
  若确需按轴累计，应另有明确名称和单位解释，不能混用同一个 duration。
- 加入数值合同示例：z=0.12 对 z 上限 0.10 应失败；三个轴同时饱和 0.1 s，
  任意轴饱和时长为 0.1 s，不是 0.3 s。示例不是仿真结果。

验收：遗漏任一轴、把较小轴限值替换为较大值、单位/聚合不符均拒绝；
正确逐轴或归一化定义通过。G3 的动态判定仍留到后续阶段。

## 修复四 初始航向可观测性与恢复目标 P1

当前初始偏差只施加给 plant truth，含 yaw 偏差；estimate 与 command 均从单位
四元数开始，却要求完整姿态真值进入约 1 度恢复带。这把未知初始航向误差当成
六轴 IMU 可消除量，与既定边界冲突。

请提出一个完整候选方案供维护者批准，而不是简单删除初始偏差测试：

- 在初始误差恢复场景中区分可观测倾斜恢复和不可观测航向误差；选择明确的
  tilt 指标或有已声明初始航向参考的相对跟踪指标。
- 如使用 yaw 初始先验，说明来源、应用时刻和误差范围，仅允许显式初始化；
  不允许持续读取 truth 或用事件名称隐式注入真值。
- 未知初始 yaw 偏差应作为限制刻画，或从必达的绝对姿态恢复条件中剥离并单独报告。
- 保留三轴相对指令跟踪，不因可观测性修复删除正常 yaw 控制验收。
- 明确四元数到倾斜/相对航向指标的定义，避免仅将完整角误差改个名字。

验收：对象、估计器、指令的初始参考关系可追溯；合同无法把未知 yaw 的绝对
恢复当作六轴可观测性能。用等价航向变换的观测不变性解释边界，不要求提前仿真。
修改验收口径须记录原因与旧口径，不表述为已经达到新指标。

## 修复五 力矩消息与饱和标记闭合 P2

当前 Controller.step 仅返回未限幅 TorqueRequest，但时序要求发布 limited_target；
Actuator.step 只接收 limited，却要报告原始 request 是否超限，信息不足。

- 选定唯一的限幅责任组件，列出 request、limited、actual、saturated 的生产者、
  消费者、消息字段、单位、时间戳和延迟。不要让多个组件以隐式规则重复限幅。
- 若由控制器产生 limited 和饱和标记，输出消息必须携带这些信息并传给执行器；
  若由执行器限幅，则其输入必须包含 request，并重新明确同 tick 回算的可用性。
- 更新 reset/step 签名和类型映射，与 antiwindup 限幅反馈及 lag 反馈的采样时刻一致；
  用 k/k-1 下标区分新目标和执行器正在追踪的旧目标，避免代数环或混用时刻。
- 给出一个 tick 的消息传递示例，证明每个输出仅依赖已声明输入/状态，不依赖隐藏全局变量。

验收：仅提供 limited 值的组件不会被要求推断 request 饱和；所有时序引用的量都有
显式接口来源。接口校验/一致性测试覆盖消息删除及生产消费不匹配。

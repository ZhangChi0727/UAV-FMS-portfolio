禁止预填未来提交、倒签审批或把 CI 成功当作冻结批准。

**审批门 D2：** PA 先评审内容与完整性，用户明确批准准确候选资产及联合冻结范围。
未批准只能标 candidate，不得标 frozen/approved/C-ready。

用户批准后写入审批事实，更新当前入口、基线状态、历史文档的清晰导航；不伪造
需求满足率、算法结果或研究结论。正式工具/编号/冻结决定都链接真实批准，不复制审批。
必要时在旧 B 单顶端加当前续单链接，保留历史，不更改受保护总单。

PA 对含批准记录的最终 head 独立复审全部差异，明确 APPROVE/REWORK。
REWORK 在同一 PR 内完成；任何新 head 要重新核对影响，旧 APPROVE 不自动继承。

**审批门 D3：** 最终 PA APPROVE、必需 CI 全绿、D1/D2 有效且用户对本 PR 的
具体合并操作明确授权后，TC 才可转 Ready/合并。视觉验收、继续执行或历史授权
均不能替代本门。默认保持 Draft；不根据其他任务的推断扩大权限。
合并前核对远端 head/base/CI；合并后记录 merge SHA、树差异、冻结资产不变、
必要检查和安全同步结果，PA 验收后才宣布 C-ready；关闭本轮 Issue 也须用户授权涵盖。

## 6 G1.5-C ready 退出条件

- [ ] B0 范围完整性矩阵已审查，适用需求有来源、责任、模型联系及足够的验证规定。
- [ ] 原子义务、条件、接口、数值引用明确；零关键 TBD、零无法解释的断链/冲突。
- [ ] 系统模型与 G0 合同一致，原生/扩展/图形/文本声明边界准确，人工检查绑定版本。
- [ ] G0/G1 历史和本轮工具测试不冒充未来产品验证，状态独立，试点历史保留。
- [ ] S/M/A 联合清单和真实 D2 冻结批准闭合，资产可取回且 hash 一致。
- [ ] 本地/CI 正反例及回归完成，精确版本阅读验收有效；保护文件未混入。

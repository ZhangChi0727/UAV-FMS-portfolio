# 补充反证 · 相同远相位，订阅服务周期化

此部分在两批常规部署测量后提出，单独解释。常规运行的远相位未发现相关提前释放的包迟到，但这不能证明 1 ms 是安全界。在独立 Linux/NATS 部署上只改变订阅应用的接收服务条件，启用周期性的服务时段，尝试主动证伪原门控。仍按同一名义源时序和冻结规则选字段。

服务周期预设为 4,492 µs，取新日志的 vehicle_attitude 源间隔中位数。以 Linux 单调时钟的固定周期网格为准，每周期前 1/4 开放服务，另外 3/4 暂停将收到的数据交给订阅应用。数据到达关闭时段就等待下一次开放。不按任何特定窗口或读取对齐，不增加专为某个反例设计的偏移。该配置是有意施加的接收调度压力，不表示原飞控或原 NATS 部署本来如此。

直接使用正式测量前已按名义条件选出的 `primary_far_latest_sat` 层的 12 个源窗口，保留 latest 策略、两批运行、每窗口两种字段臂，合计 48 次。全部选中运行均为远相位 none。对照相同源窗口的常规部署；分别计入提交给发送 socket 前迟到、已提交但读取之后才进应用队列、实际需求是否翻转，以及在 one 执行上开放字段能否纠正。未出现反例也要保留。比较基于不同真实执行，不能把时延精确拆分为网络、代理或 OS 各自的开销。
